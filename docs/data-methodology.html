Northwind CRM case / Data methodology

Data methodology

How the tables were understood, validated, cleaned and joined · Companion to the Analysis

We got three raw extracts and no data dictionary. The tables join cleanly on ids (99%+ match rates), but they needed 14 fixes before we could trust them: duplicates, broken keys, amounts recorded 1,000× too high, a sign bug in days to close, out-of-range dates and messy labels. Under 1% of rows needed a fix (not counting URL normalization, which applies to every visit). Every rule is in SQL and every count on this page is queried from the data.

4. Definitions

  • Paying customer (win): an opportunity with amount > $0, closed within 30 days of the signup. We call it "paying customer" because finance defines a customer as a closed opportunity, and $0 deals don't pay.
  • Cohort: signups grouped by the month they signed up. Conversion is always cohort-based (signup month → did they pay), not close-month based.
  • Periods: Q1 = Jan–Mar 2026 (before Free CRM), Q2 = Apr–Jun 2026 (after launch). Compared as monthly averages.
  • Plan: the product the lead signed up for (product_code), not the plan they bought.
  • Origin attributes (channel, entry page, device): from the signup session, i.e. last touch. 37% of signups had earlier visits; we don't attribute to those.
  • New vs returning: returning = the visitor had a session on an earlier day than the signup.

5. Assumptions and why they're safe

  • 30-day window. No deal in the extract closes more than 29 days after signup, so a 30-day window loses nothing. Opportunities run to Jul 26; the 166 signups after Jun 26 have a slightly shorter window. With a 29-day maximum, the impact is a handful of deals in late June.
  • $0 deals excluded. 30 of 1,495 deals, spread evenly across months. Including them doesn't change any trend (see the finance view in the analysis).
  • Orphan rows kept, not invented. We don't guess the true keys of the 25 signups and 15 deals with broken ids. They stay in the totals they can support and out of the cuts they can't.
  • January in the finance view. Some January closes come from December signups, which aren't in the data, so January close-month counts are low. Cohort views aren't affected.
  • Free CRM in the decomposition. Free CRM has no Q1 conversion rate. The Kitagawa split uses its Q2 rate for both periods, which puts its whole effect in the mix term.

6. What the data can't tell us

  • Anything inside the product. Sessions are website visits; there are no product logins or usage events. We can't measure activation.
  • Upgrades after 30 days. No deal closes more than 29 days after signup, for any SKU, even for April cohorts with ~85 days of history. Either Free CRM users decide in their first month or the extract only captures the first 30 days. A freemium plan usually converts over a longer period, so Free CRM's lifetime conversion could be higher than what we observe.
  • Multi-touch attribution. Only the signup session is linked to the lead.
  • Direct traffic in June. Direct jumps to 37% of sessions and its signup rate halves. Probably tracking or bots; worth checking at the source.

7. Reproduce it

Requires DuckDB. From the repo root, run the three files in order. Engine-specific functions (read_csv_auto, date_trunc, date_diff) have direct equivalents in Snowflake or BigQuery.

duckdb northwind.duckdb < sql/01_clean.sql

01_clean.sql — cleaning rules and analysis base table
-- =====================================================================
-- 01_clean.sql — Northwind CRM: raw CSVs -> cleaned tables
-- Engine: DuckDB (standard SQL; reads CSVs directly).
-- Every rule is numbered (R1..R14) and matches the data-validation doc.
-- =====================================================================

-- ---------------------------------------------------------------------
-- SESSIONS  (1 row = 1 website visit)
-- ---------------------------------------------------------------------
CREATE OR REPLACE TABLE sessions_clean AS
WITH raw AS (
    SELECT * FROM read_csv_auto('data/sessions.csv')
),
url AS (
    SELECT
        *,
        -- R2: normalize URL: lowercase, drop query string, drop geo prefix, drop trailing slash
        COALESCE(NULLIF(
            regexp_replace(
                regexp_replace(lower(split_part(entry_url, '?', 1)), '^/(uk|in|de|au|ca)(/|$)', '/'),
            '/+$', ''),
        ''), '/') AS url_norm
    FROM raw
)
SELECT
    session_id,
    visitor_id,
    CAST(event_dt AS DATE)                  AS event_dt,
    -- R1: channel labels have casing / trailing-space variants ("Display ", "direct")
    CASE lower(trim(mktg_channel))
        WHEN 'direct'         THEN 'Direct'
        WHEN 'display'        THEN 'Display'
        WHEN 'email'          THEN 'Email'
        WHEN 'organic search' THEN 'Organic Search'
        WHEN 'paid search'    THEN 'Paid Search'
        WHEN 'referral'       THEN 'Referral'
        WHEN 'social'         THEN 'Social'
    END                                      AS mktg_channel,
    geo,
    device_type,
    entry_url,
    -- R2: 135 raw URLs -> 7 page types
    CASE
        WHEN url_norm LIKE '/blog%' OR url_norm LIKE '/resources%'    THEN 'content'
        WHEN url_norm IN ('/', '/home', '/index')                     THEN 'home'
        WHEN url_norm LIKE '/pricing%' OR url_norm LIKE '/plans%'     THEN 'pricing'
        WHEN url_norm IN ('/offers/free-crm', '/lp/free-crm')         THEN 'free_crm_lp'
        WHEN url_norm = '/get/starter-trial'                          THEN 'trial_lp'
        WHEN url_norm IN ('/go/crm', '/campaign/spring-2026')         THEN 'campaign_lp'
        WHEN url_norm LIKE '/product%' OR url_norm LIKE '/features%'  THEN 'product'
        ELSE 'other'
    END                                      AS page_type,
    converted_flag,
    -- R3: 300 sessions without visitor_id: kept, flagged
    visitor_id IS NULL                       AS visitor_missing
FROM url;

-- ---------------------------------------------------------------------
-- SIGNUPS  (1 row = 1 lead = 1 product signup)
-- ---------------------------------------------------------------------
CREATE OR REPLACE TABLE signups_clean AS
WITH dedup AS (
    -- R4: drop exact duplicate rows
    SELECT DISTINCT * FROM read_csv_auto('data/signups.csv')
),
sized AS (
    SELECT
        * REPLACE (
            -- R5: company_size sentinels (-5, 999999) -> NULL
            CASE WHEN company_size < 1 OR company_size >= 999999 THEN NULL
                 ELSE company_size END AS company_size,
            -- R14: geo holds the literal text 'N/A' in 25 rows (plus 25 true NULLs) -> NULL
            NULLIF(trim(geo), 'N/A') AS geo
        )
    FROM dedup
),
ranked AS (
    -- R6: same lead_id twice with conflicting attributes -> keep the most complete row
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY lead_id
            ORDER BY (geo IS NOT NULL)::INT + (company_size IS NOT NULL)::INT DESC
        ) AS rn
    FROM sized
)
SELECT
    r.lead_id,
    r.visitor_id,
    r.session_id,
    -- R7: 8 signups dated July (outside window); 99.9% of signups happen the same
    --     day as their session -> replace with the session date
    CASE WHEN CAST(r.created_dt AS DATE) > DATE '2026-06-30' AND s.event_dt IS NOT NULL
         THEN s.event_dt ELSE CAST(r.created_dt AS DATE) END          AS created_dt,
    CAST(r.created_dt AS DATE) > DATE '2026-06-30'
         AND s.event_dt IS NOT NULL                                     AS created_dt_imputed,
    r.mktg_channel,
    r.product_code,
    CASE r.product_code WHEN 'STR' THEN 'Starter'
                        WHEN 'PRO' THEN 'Pro'
                        WHEN 'FCRM' THEN 'Free CRM' END                 AS product,
    r.geo,
    r.company_size,
    -- R8: session_id not found in sessions (malformed key S9xxxxxxx): kept, flagged
    s.session_id IS NULL                                                AS session_orphan
FROM ranked r
LEFT JOIN sessions_clean s USING (session_id)
WHERE r.rn = 1;

-- ---------------------------------------------------------------------
-- OPPORTUNITIES  (1 row = 1 closed deal)
-- ---------------------------------------------------------------------
CREATE OR REPLACE TABLE opportunities_clean AS
WITH dedup AS (
    -- R9: drop exact duplicate rows
    SELECT DISTINCT * FROM read_csv_auto('data/opportunities.csv')
)
SELECT
    o.opp_id,
    o.lead_id,
    CAST(o.close_dt AS DATE)                                            AS close_dt,
    o.plan,
    -- R10: amounts 1000x list price (35000 / 110000) -> unit error, divide by 1000
    CASE WHEN o.amount IN (35000, 110000) THEN o.amount // 1000
         ELSE o.amount END                                              AS amount,
    -- R11: $0 deals: closed but not paying -> excluded from "paying customers"
    o.amount = 0                                                        AS zero_amount,
    -- R12: negative days_to_close is a sign bug -> recompute from dates
    COALESCE(date_diff('day', g.created_dt, CAST(o.close_dt AS DATE)),
             abs(o.days_to_close))                                      AS days_to_close,
    -- R13: lead_id not found in signups (malformed key G9xxxxxx): kept, flagged
    g.lead_id IS NULL                                                   AS lead_orphan
FROM dedup o
LEFT JOIN signups_clean g USING (lead_id);

-- ---------------------------------------------------------------------
-- ANALYSIS BASE: 1 row per signup with origin attributes + 30-day win
-- ---------------------------------------------------------------------
CREATE OR REPLACE TABLE signup_outcomes AS
WITH first_visit AS (
    SELECT visitor_id, MIN(event_dt) AS first_visit_dt
    FROM sessions_clean
    WHERE visitor_id IS NOT NULL
    GROUP BY visitor_id
)
SELECT
    g.*,
    date_trunc('month', g.created_dt)::DATE                             AS signup_month,
    CASE WHEN g.created_dt < DATE '2026-04-01' THEN 'Q1' ELSE 'Q2' END  AS period,
    s.device_type,
    s.page_type,
    CASE WHEN fv.first_visit_dt < g.created_dt THEN 'Returning' ELSE 'New' END AS visitor_type,
    CASE WHEN g.company_size IS NULL THEN 'Unknown'
         WHEN g.company_size <= 10  THEN '1-10'
         WHEN g.company_size <= 50  THEN '11-50'
         WHEN g.company_size <= 200 THEN '51-200'
         ELSE '201+' END                                                AS company_size_bucket,
    o.plan                                                              AS won_plan,
    o.amount                                                            AS won_amount,
    o.days_to_close,
    -- Win definition: paying (amount > 0) opp closed within 30 days of signup
    (o.opp_id IS NOT NULL AND o.days_to_close <= 30)                    AS win_30d
FROM signups_clean g
LEFT JOIN sessions_clean s       USING (session_id)
LEFT JOIN first_visit fv         ON fv.visitor_id = g.visitor_id
LEFT JOIN opportunities_clean o  ON o.lead_id = g.lead_id AND NOT o.zero_amount;
02_funnel.sql — funnel, plan split, slices, finance view
-- =====================================================================
-- 02_funnel.sql — Funnel metrics on cleaned data. Requires 01_clean.sql.
-- Win = paying opp (amount > 0) closed within 30 days of signup.
-- =====================================================================

-- 1. Monthly cohort funnel: sessions -> signups -> 30-day wins -> new MRR
CREATE OR REPLACE TABLE monthly_funnel AS
WITH sess AS (
    SELECT date_trunc('month', event_dt)::DATE AS month, COUNT(*) AS sessions
    FROM sessions_clean GROUP BY 1
),
sig AS (
    SELECT signup_month AS month,
           COUNT(*)                                             AS signups,
           SUM(win_30d::INT)                                    AS wins_30d,
           SUM(CASE WHEN win_30d THEN won_amount ELSE 0 END)    AS new_mrr_30d
    FROM signup_outcomes GROUP BY 1
)
SELECT month, sessions, signups, wins_30d, new_mrr_30d,
       ROUND(100.0 * signups  / sessions, 2) AS sess_to_signup_pct,
       ROUND(100.0 * wins_30d / signups, 1)  AS signup_to_win_pct,
       ROUND(100.0 * wins_30d / sessions, 2) AS sess_to_win_pct
FROM sess JOIN sig USING (month)
ORDER BY month;

-- 2. Same funnel split by product (mix, conversion, wins, MRR)
CREATE OR REPLACE TABLE product_funnel AS
SELECT signup_month AS month, product,
       COUNT(*)                                                      AS signups,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY signup_month), 1) AS mix_pct,
       SUM(win_30d::INT)                                             AS wins_30d,
       ROUND(100.0 * AVG(win_30d::INT), 1)                           AS signup_to_win_pct,
       SUM(CASE WHEN win_30d THEN won_amount ELSE 0 END)             AS new_mrr_30d
FROM signup_outcomes
GROUP BY signup_month, product
ORDER BY month, product;

-- 3. Signup -> win conversion by origin slice, monthly + Q1 vs Q2
--    (long format: one row per dimension x value x month)
CREATE OR REPLACE TABLE slice_conversion AS
WITH long AS (
    SELECT signup_month, period, win_30d, product, 'channel'      AS dimension, mktg_channel        AS value FROM signup_outcomes
    UNION ALL SELECT signup_month, period, win_30d, product, 'entry_page',   page_type           FROM signup_outcomes
    UNION ALL SELECT signup_month, period, win_30d, product, 'device',       device_type         FROM signup_outcomes
    UNION ALL SELECT signup_month, period, win_30d, product, 'visitor_type', visitor_type        FROM signup_outcomes
    UNION ALL SELECT signup_month, period, win_30d, product, 'company_size', company_size_bucket FROM signup_outcomes
    UNION ALL SELECT signup_month, period, win_30d, product, 'geo',          COALESCE(geo, 'Unknown') FROM signup_outcomes
)
SELECT dimension, value,
       strftime(signup_month, '%Y-%m')                   AS month,
       period,
       COUNT(*)                                          AS signups,
       SUM(win_30d::INT)                                 AS wins_30d,
       ROUND(100.0 * AVG(win_30d::INT), 1)               AS signup_to_win_pct,
       ROUND(100.0 * AVG((product = 'Free CRM')::INT), 1) AS free_crm_share_pct
FROM long
WHERE value IS NOT NULL            -- drops 25 signups with no matching session
GROUP BY dimension, value, signup_month, period
ORDER BY dimension, value, month;

-- 4. Finance view: paying customers by CLOSE month (incl. orphan opps)
CREATE OR REPLACE TABLE finance_view AS
SELECT date_trunc('month', close_dt)::DATE AS close_month,
       COUNT(*) FILTER (WHERE NOT zero_amount)         AS paying_customers,
       COUNT(*)                                         AS all_closed_opps,
       SUM(amount)                                      AS new_mrr
FROM opportunities_clean
GROUP BY 1 ORDER BY 1;

SELECT * FROM monthly_funnel;
03_decomposition.sql — Kitagawa decomposition
-- =====================================================================
-- 03_decomposition.sql — Kitagawa decomposition of the change in
-- paying customers (30-day wins) per month, Q1 vs Q2 2026.
--
--   Wins = N x R            N = signups / month,  R = blended conversion
--   R    = SUM_i m_i x r_i  m_i = product mix share, r_i = product conversion
--
-- Exact symmetric (Kitagawa) split, using period averages (bar):
--   dWins  = dN x R_bar                        -> VOLUME effect
--          + N_bar x SUM_i dm_i x r_bar_i      -> MIX effect   (by product)
--          + N_bar x SUM_i m_bar_i x dr_i      -> RATE effect  (by product)
--
-- Assumption: Free CRM did not exist in Q1, so it has no Q1 rate.
-- We set r_Q1(Free) = r_Q2(Free): Free contributes no rate effect and its
-- whole impact is counted as mix. Requires 01_clean.sql.
-- =====================================================================

CREATE OR REPLACE TABLE kitagawa AS
WITH by_product AS (
    SELECT period, product,
           COUNT(*) / 3.0                AS signups_mo,
           SUM(win_30d::INT) / 3.0       AS wins_mo
    FROM signup_outcomes
    GROUP BY ALL
),
grid AS (   -- every product in both periods (Free CRM has zero Q1 signups)
    SELECT p.period, pr.product
    FROM (VALUES ('Q1'), ('Q2')) p(period)
    CROSS JOIN (SELECT DISTINCT product FROM signup_outcomes) pr
),
filled AS (
    SELECT g.period, g.product,
           COALESCE(b.signups_mo, 0) AS signups_mo,
           COALESCE(b.wins_mo, 0)    AS wins_mo
    FROM grid g LEFT JOIN by_product b USING (period, product)
),
shares AS (
    SELECT *,
           signups_mo / SUM(signups_mo) OVER (PARTITION BY period) AS mix,
           wins_mo / NULLIF(signups_mo, 0)                         AS rate
    FROM filled
),
wide AS (
    SELECT q1.product,
           q1.mix AS mix_q1, q2.mix AS mix_q2,
           COALESCE(q1.rate, q2.rate) AS rate_q1,   -- Free CRM assumption
           q2.rate AS rate_q2
    FROM shares q1 JOIN shares q2 USING (product)
    WHERE q1.period = 'Q1' AND q2.period = 'Q2'
),
totals AS (
    SELECT period, SUM(signups_mo) AS n, SUM(wins_mo) AS w, SUM(wins_mo) / SUM(signups_mo) AS r
    FROM filled GROUP BY period
),
t AS (
    SELECT q1.n AS n1, q2.n AS n2, q1.w AS w1, q2.w AS w2, q1.r AS r1, q2.r AS r2
    FROM totals q1, totals q2 WHERE q1.period = 'Q1' AND q2.period = 'Q2'
)
SELECT 'Q1 wins / month' AS step, NULL AS product, w1 AS wins FROM t
UNION ALL
SELECT 'Volume effect', NULL, (n2 - n1) * (r1 + r2) / 2 FROM t
UNION ALL
SELECT 'Mix effect', w.product,
       (t.n1 + t.n2) / 2 * (w.mix_q2 - w.mix_q1) * (w.rate_q1 + w.rate_q2) / 2
FROM wide w, t
UNION ALL
SELECT 'Rate effect', w.product,
       (t.n1 + t.n2) / 2 * (w.mix_q1 + w.mix_q2) / 2 * (w.rate_q2 - w.rate_q1)
FROM wide w, t
UNION ALL
SELECT 'Q2 wins / month', NULL, w2 FROM t;

-- Waterfall view (one bar per effect)
SELECT step, ROUND(SUM(wins), 1) AS wins_per_month
FROM kitagawa
GROUP BY step
ORDER BY CASE step WHEN 'Q1 wins / month' THEN 1 WHEN 'Volume effect' THEN 2
                   WHEN 'Mix effect' THEN 3 WHEN 'Rate effect' THEN 4 ELSE 5 END;
